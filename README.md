# Frontend: навыки, зарплаты и MapReduce

Вариант **8. Программист, разработчик Frontend**. Основной результат — [report.pdf](report.pdf). В [report.md](report.md) — тот же отчёт в редактируемом виде. Все числа получены собственными запусками из S3; журналы и таблицы сохранены рядом с кодом.

Репозиторий: [Arsenyyya/VK_ed_hw](https://github.com/Arsenyyya/VK_ed_hw).

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
mkdir -p runtime/disks/{disk1,disk2,disk3,disk4}
chmod 777 runtime/disks runtime/disks/disk*
docker compose up -d
.venv/bin/python scripts/install_extension.py
.venv/bin/python scripts/storage.py
.venv/bin/python scripts/check_algorithms.py
.venv/bin/python scripts/analyze.py
.venv/bin/python scripts/benchmark.py
.venv/bin/python scripts/verify.py
.venv/bin/python scripts/build_report.py
.venv/bin/python scripts/render_pdf.py
```

Исходный `it_vacancies_2024.csv` повторно используется из соседней предыдущей работы: `../rustfs_lab/data/it_vacancies_2024.csv`. Для другой машины положите оригинальный CSV в `data/` и измените `source_path` в [config.json](config.json) на `data/it_vacancies_2024.csv`. Контрольная сумма — в [logs/storage.json](logs/storage.json). Исходный CSV объёмом 808 МиБ и внутренние диски RustFS не включены в Git.

S3: http://127.0.0.1:19100. Консоль: http://127.0.0.1:19101/rustfs/console/index.html. Локальные учебные реквизиты: `labadmin` / `local-lab-secret-2026`. Новый контейнер и диски находятся внутри этой работы и не используют диски прошлой лабораторной. Остановка: `docker compose stop`.

## Где что лежит

| Файл | Назначение |
| --- | --- |
| `config.json` | Вариант, явный фильтр роли и названия, три размера стека, регионы |
| `scripts/mapreduce.py` | Потоковое чтение S3, 4 процесса, MapReduce, combiner и восстановление после смерти маппера |
| `sql/prepare.sql`, `sql/count.sql` | Самостоятельная фильтрация и независимый SQL-подсчёт |
| `sql/analysis.sql` | Медианы, базовые сочетания и две региональные таблицы |
| `logs/benchmark.json` | Каждый замер времени и пикового RSS, команды, коды завершения |
| `results/verification.json` | Полная сверка всех ключей и значений, включая обратное чтение результатов из S3 |
| `results/skill_frequencies.csv` | Частоты всех одиночных навыков, пар и троек |
| `results/salary_effects.csv` | Все подходящие по размеру зарплатной выборки сравнения с базой |
| `results/regions_summary.csv`, `results/regions_skills.csv` | Зарплаты и навыки/пары/тройки трёх регионов |
| `results/selected_vacancies.csv` | Воспроизводимая выборка варианта без описаний и персональных данных |
| `evidence/` | Снимки Terminal и графики |

Результаты каждого запуска лежат также в `s3://hh-lake/results/`. Частота — число вакансий с сочетанием, дубликаты навыка внутри вакансии удаляются. В тестах масштабирования берутся первые 5, 10 или 15 различных нормализованных навыков в алфавитном порядке; для аналитики используются **полные** стеки. Разные написания, например `html` и `html5`, не склеиваются.

В зарплатном анализе используются только положительные рублёвые суммы «на руки» (`gross=false`): середина диапазона или единственная указанная граница. Минимум — 10 зарплатных наблюдений. Для пары база — более частый одиночный навык; для тройки — более частая пара. Сравнение описывает связи в выборке.

Профилирование: три свежих процесса на каждый из 3 размеров и 3 режимов, всего 27 замеров, плюс полный стек и восстановление. Время включает S3-чтение и запись результата. RSS дерева клиентских процессов опрашивается каждые 10 мс; Docker/RustFS не включён, разделяемые страницы могут учитываться несколько раз. Серверный и системный кеши не сбрасываются; порядок режимов меняется между попытками.

Проверка отказа действительно завершает один процесс маппера через `os._exit(17)`. Частичные счётчики отбрасываются; задача один раз заново читает S3. Запись итогового объекта происходит только после успешного расчёта. Итог сверяется со штатным MapReduce и DuckDB.
